
This is an alpha quality "cyber reasoning engine" for libcurl. It runs
incrementally so that it doesn't exhaust your AI subscription. The AI works in
two stages. In the first stage the AI is given scan_prompt.txt and asked to find
an exploit in a .c file. In the second stage it is given exploit_prompt.txt and
asked to write a Python script that proves the exploit exists and can trigger an
ASAN exception.

There is an adversarial relationship between scan_prompt.txt and
exploit_prompt.txt. Using a second invocation of an AI to verify initial
findings tends to provide better quality signal.

So far this has only been tested with Claude Sonnet as Claude Opus was refusing
to write exploits. The code is also still slightly brittle as it is vibe coded
trash and not a carefully written attack surface. Only the src and lib
directories are scanned.

Traditional cyber reasoning engines are driven by static analyzers as well. This
was not done in this case as the assumption was made that static analysis had
already been done and the results carefully checked.

build.sh - Build debug libcurl with the address sanitizer enabled.
clean.sh - Use git to delete everything in .gitignore.
clean_sweep.sh - Delete the current state of the vulnerability state.
init_sweep.sh - Initialize, but do not start a vulnerability sweep.
run.sh <exploit_script> - Execute a script generated by the exploit agent.
run_sweep.sh <number_of_files_to_scan> - Sweep through some number of files.
